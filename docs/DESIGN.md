# Volm 設計書

Volm は、タスクバー上のマウスホイールで音量を、Ctrl+ホイールでモニターの明るさを変える Windows 用の常駐アプリである。日常的に使う機能だけに絞った軽量なアプリとして、Go と MyGo で作る。

- 対象 OS: Windows 10 / 11 (x64)。他の OS には対応しない
- ライセンス: GPL-3.0-only
- リポジトリ: github.com/otnc/Volm (Go のモジュールパスも同じ)
- 作者: otoneko.
- 配布: Inno Setup のインストーラーと GitHub Releases
- 文書の状態: 初版 (2026-11-25)。「要検証」と書いた項目は PoC で確かめてから確定する

## 1. 目的と範囲

Volm の中心になる機能は次のとおり。

- タスクバー上のホイールで音量を変える
- タスクバー上の中クリックでミュートを切り替える
- 画面右下に OSD (音量の表示) を出す
- ホットキー: Win+↑/↓ で音量、Ctrl+Shift+Q で再生/一時停止、Ctrl+Shift+E で次の曲

これに、明るさ調整、アプリ別音量、出力デバイスの切り替え、設定画面からのアップデートを加える。

### 対象にしないもの

- Windows 以外の OS
- 画面端でのホイール操作、ピークメーター、スキンの切り替え
- 多言語対応 (UI は日本語のみ)
- 録音デバイスの操作

## 2. 機能仕様

### 2.1 タスクバー上のマウス操作

マウスカーソルの下のウィンドウがタスクバーのときだけ、ホイールとクリックを Volm が処理する。処理したイベントは他のアプリに渡さない。タスクバー以外の場所では何もしない。

| 操作 | 動作 |
|---|---|
| ホイール | 既定の再生デバイスの音量を上げ下げする |
| Ctrl+ホイール | カーソルがあるモニターの明るさを上げ下げする |
| Ctrl+Shift+ホイール | すべてのモニターの明るさを同じ量だけ上げ下げする |
| Alt+ホイール (アプリのボタン上) | そのアプリの音量だけを上げ下げする (2.4) |
| 中クリック | 既定の再生デバイスのミュートを切り替える |

タスクバーの判定では、カーソル位置のウィンドウのルートウィンドウのクラス名を見る。メインモニターのタスクバーは `Shell_TrayWnd`、ほかのモニターのタスクバーは `Shell_SecondaryTrayWnd` である。通知領域や時計もタスクバーの一部として扱う。

変化量は 1 ノッチ (ホイールの delta 120) あたり音量 2%、明るさ 5% を初期値とし、設定画面で 1〜20% の範囲で変えられる。高精度ホイールやタッチパッドは 120 未満の delta を細かく送るので、delta を積算し、120 に達するごとに 1 ノッチとして扱う。

### 2.2 音量

既定の再生デバイス (eRender / eMultimedia) のマスター音量を Core Audio の `IAudioEndpointVolume` で変える。音量はスカラー値 (0.0〜1.0) で扱い、表示は 0〜100% の整数にする。

音量を上げたときにミュート中なら、ミュートを解除する。この挙動は設定でオフにできる。既定のデバイスが変わったら (`IMMNotificationClient` で通知を受ける)、操作対象を新しいデバイスに切り替える。

### 2.3 明るさ

モニターごとに、使える方法を次の順で調べて決める。

1. WMI (`root\wmi` の `WmiMonitorBrightnessMethods`)。ノート PC の内蔵パネルで使える
2. DDC/CI (`dxva2.dll` の `SetMonitorBrightness`、使えなければ VCP コード 0x10)。外部モニターで使える
3. ソフト減光。上の 2 つが使えないモニターでは、画面全体を覆う半透明の黒いウィンドウで暗くする

ソフト減光は暗くすることしかできない。明るさ 100% は「覆いなし」を表す。真っ暗になって操作できなくなるのを防ぐため、下限を設け、初期値は 20% とする。覆いのウィンドウはクリックを透過し、最前面に置き、タスクバーにもタスク切り替えにも出さない。マウスカーソルは暗くならない。

設定画面では、検出した方法をモニターごとに表示し、手動で別の方法 (ソフト減光、または無効) に変えられるようにする。

DDC/CI は 1 回の読み書きに数十ミリ秒かかり、モニターによっては連続した書き込みを取りこぼす。そのため、モニターごとに書き込み用のワーカーを 1 つ置き、ホイール操作中は目標値だけを更新して、ワーカーが最新の目標値を順に書き込む。起動時と、ディスプレイの構成が変わったとき (`WM_DISPLAYCHANGE`) に、モニター一覧と使える方法を調べ直す。

HMONITOR と WMI のインスタンスは、`EnumDisplayDevices` に `EDD_GET_DEVICE_INTERFACE_NAME` を付けて得るデバイスインターフェース名で対応づける。インターフェース名 `\\?\DISPLAY#SHP158C#4&1227b4ea&0&UID8388688#{e6f07b5f-...}` から先頭の `\\?\` と末尾の `#{GUID}` を除き、`#` を `\` に置き換えると、WMI の `InstanceName` (`DISPLAY\SHP158C\4&1227b4ea&0&UID8388688_0`) から末尾の `_0` を除いたものと一致する (PoC 3 で確認)。大文字と小文字は区別せずに比べる。

#### この端末での調査結果 (2026-11-25)

| モニター | 接続 | WMI | DDC/CI |
|---|---|---|---|
| LQ140N1JW03 (SHP158C、メイン) | 内蔵 | 読み取りできた (100) | 応答なし |
| HP 2009 (HWP2827) | 外部 | 対象外 | 応答なし |
| TOSHIBA LCB2005V (TSB0209) | 外部 | 対象外 | 応答なし |

内蔵パネルは WMI で変えられる見込みが高い。外部の 2 台は `GetMonitorBrightness` と VCP 0x10 の読み取りがどちらも失敗した。原因の候補は、モニターのメニューで DDC/CI がオフになっていること、変換アダプターやドック経由の接続、テレビ系の機種で DDC/CI に対応していないこと、である (要検証)。DDC/CI が使えない場合も、ソフト減光で暗くすることはできる。

### 2.4 アプリ別音量

タスクバーのアプリのボタンの上で Alt+ホイールを回すと、そのアプリの音声セッションの音量だけを変える。OSD にはアプリ名と音量を表示する。

1. UI Automation の `ElementFromPoint` で、カーソルの下にあるタスクバーのボタンを取得する
2. ボタンの AutomationId (`Appid: <AUMID>`) から AUMID を取り出す。AUMID が `{既知フォルダーの GUID}\相対パス` の形なら、`SHGetKnownFolderPath` で絶対パスに戻す
3. 表示中のトップレベルウィンドウを列挙し、AUMID が一致するウィンドウのプロセスの実行ファイルを集める。ウィンドウの AUMID は `SHGetPropertyStoreForWindow` の `PKEY_AppUserModel_ID` で取り、なければパッケージアプリの AUMID (`GetApplicationUserModelId`)、それもなければ実行ファイルのパスで代える
4. `IAudioSessionManager2` で既定デバイスのセッションを列挙する。セッションのプロセスの AUMID が一致するか、実行ファイルが 3 で集めたものと同じセッションの `ISimpleAudioVolume` を変える

ブラウザーは、ウィンドウのプロセスとは別の子プロセスで音を鳴らす。そのため、プロセス ID ではなく実行ファイルで比べる。この方法では、同じ実行ファイルで動くアプリ (Brave の本体と Brave で入れた PWA など) の音量を分けて変えられない。

同じアプリのセッションが複数あれば、すべてに同じ音量を設定する。一致するセッションがなければ、OSD に「音声セッションなし」と表示して何もしない。Windows 10 のタスクバーでの動作は確かめていない。

### 2.5 出力デバイスの切り替え

トレイメニューの「出力デバイス」に有効な再生デバイスを並べ、選んだデバイスを既定にする。既定の設定には非公開 COM インターフェースの `IPolicyConfig` (`CPolicyConfigClient`) を使い、eConsole、eMultimedia、eCommunications の 3 つの役割をまとめて切り替える。

`IPolicyConfig` は Microsoft が公開していない API で、Windows のアップデートで使えなくなる可能性がある。呼び出しに失敗したら、エラーを通知し、Windows のサウンド設定 (`ms-settings:sound`) を開く。

### 2.6 OSD

音量、ミュート、明るさ、アプリ別音量を変えたとき、操作したモニターに OSD を出す。

- 表示内容: アイコン、対象の名前 (デバイス名、モニター名、アプリ名)、バーと数値 (%)
- 位置: 操作したモニターの作業領域の右下 (初期値)。設定で四隅と中央下から選ぶ
- 表示時間: 最後の操作から 1.5 秒後にフェードアウトする (初期値)
- フォーカスを奪わず、クリックを透過し、タスクバーに出さない
- テーマ: Windows のライト/ダークに合わせる

OSD は MyGo のウィンドウではなく、Win32 のレイヤードウィンドウに GDI で描いて作る。MyGo の小さなウィンドウ (`Panel`、`Frameless`、`Transparent`) を 1 つ作って隠しておくだけで、常駐プロセスのワーキングセットが 20MB から 91MB に増えたためである (2026-11-26 に計測)。OSD のウィンドウは専用のスレッドで起動時に 1 つ作って隠しておき、表示のたびに位置と内容だけを変える。角は DWM で丸め、フェードアウトはウィンドウ全体の不透明度で行う。

### 2.7 ホットキー

設定画面で、次のアクションにキーの組み合わせを割り当てる。1 つのアクションに割り当てられるキーは 2 つまでとする。

| アクション | 初期値 |
|---|---|
| 音量を上げる | Win+↑ |
| 音量を下げる | Win+↓ |
| ミュート切り替え | なし |
| 明るさを上げる (カーソルのあるモニター) | なし |
| 明るさを下げる (カーソルのあるモニター) | なし |
| 再生/一時停止 | Ctrl+Shift+Q |
| 次の曲 | Ctrl+Shift+E |
| 前の曲 | なし |
| 出力デバイスを順に切り替える | なし |

Win+↑/↓ は Windows がウィンドウの最大化とスナップに使っており、`RegisterHotKey` では登録できない。そのため、Volm はホットキーをすべて低レベルキーボードフック (`WH_KEYBOARD_LL`) で判定し、一致したキー入力は他のアプリに渡さない。MyGo の `GlobalShortcut` は使わない。

Win を含む組み合わせを処理したら、Win が押されている間に `VK_NONAME` (0xFC) の押下と解放を `SendInput` で送る。送らないと、Win を離したときにスタートメニューが開く (PoC 7)。Alt を含む組み合わせも、メニューバーにフォーカスが移るのを防ぐために同じようにする。

メディア操作 (再生/一時停止、次の曲、前の曲) は、`SendInput` でメディアキー (`VK_MEDIA_PLAY_PAUSE` など) を送って実現する。

### 2.8 トレイアイコン

- アイコン: 音量に応じて 4 段階 (ミュート、低、中、高) に切り替える
- ツールチップ: `音量 40% / スピーカー (Realtek)` のように音量と既定デバイス名を出す
- 左クリック: 設定画面を開く
- 右クリックのメニュー: ミュート (チェック)、出力デバイス (サブメニュー、ラジオ)、設定、更新を確認、終了

MyGo v0.10.0 は `TaskbarCreated` を受け取ると、トレイアイコンを登録し直す (ソースで確認した)。Explorer を再起動したときの動作は、実機ではまだ確かめていない。

### 2.9 設定画面

MyGo のネイティブ UI で作る。タブで次の項目を分ける。設定は変更した時点で反映して保存し、「保存」ボタンは置かない。

| タブ | 項目 |
|---|---|
| 一般 | Windows 起動時に起動 (初期値はオン)、音量を上げたらミュートを解除、Volm の再起動と終了 |
| 音量 | タスクバーのホイールで音量を変える (オフにするとホイールはほかのアプリに渡る)、1 ノッチの変化量、中クリックでミュート、Alt+ホイールでアプリ別音量 |
| 明るさ | タスクバーのホイールで明るさを変える (同上)、1 ノッチの変化量、モニターごとの方法 (自動 / WMI / DDC/CI / ソフト減光 / 無効) と現在の値、ソフト減光の下限 |
| ホットキー | アクションごとのキー割り当て、割り当ての削除 |
| OSD | 表示する/しない、位置、表示時間 |
| 更新 | 現在のバージョン、「更新を確認」ボタン、起動時に確認する、プレリリースも対象にする |
| 情報 | バージョン、作者 (otoneko.)、ライセンス (GPL-3.0)、使っているライブラリのライセンス |

画面は、左に項目のアイコン付きのページ一覧、右に設定項目のカードを並べる。各カードには Material Symbols (Rounded) のアイコン、項目名、1 行の説明、操作部品を置く。項目のアイコンは Volm のアイコンのタイルと同じ藍色にし、スイッチなどの操作部品は Windows のアクセントカラーに従う。2026-11-26 の時点で実装したのは「一般」「音量」「OSD」「情報」の 4 ページで、「明るさ」「ホットキー」「更新」のページは、それぞれの機能と一緒に足す。

ホットキーのページでは、操作ごとの「追加」を押すと記録モードになり、次に押したキーの組み合わせを記録する。記録には設定画面のプロセスが低レベルキーボードフックを使う。あとから登録したフックが先に呼ばれるので、常駐プロセスのホットキーとして割り当て済みの組み合わせも、実行されずに記録される。Esc は取り消しになる。すでに別の操作に割り当てたキーを記録したら、どの操作と重複しているかを表示し、上書きするかを確認する。

常駐プロセスのキーボードフックは、Volm 自身が送った入力 (`dwExtraInfo` に印を付けたもの) だけを素通りさせる。ほかのアプリが送った入力は、キーボードからの入力と同じに扱う。リモートデスクトップなどの遠隔操作のツールは、キー入力を送り込む形で操作を伝えるので、それを素通りさせるとホットキーが効かなくなるためである。

各項目の右端には、その項目だけを初期値に戻すアイコンのボタンを置く。確認は挟まない (戻したあとでもすぐに変え直せるため)。今が初期値の項目では押せない状態にして、初期値かどうかが見てわかるようにする。ホットキーでは操作ごと、明るさではモニターごとに置く。

画面の下部に「初期値に戻す」ボタンを置く。押すと確認ダイアログを出し、了承したらすべての設定 (ホットキーとモニターごとの方法を含む) を初期値に戻して保存する。「Windows 起動時に起動」も初期値 (オン) に戻し、Run の登録もそれに合わせる。

設定画面は常駐するプロセスとは別のプロセス (`volm.exe --settings`) で開く。PoC 1 では、同じプロセスで設定画面を一度開くと、閉じたあとも常駐時のメモリが 20MB から 42〜52MB に増えたままになった。別のプロセスにすれば、設定画面を閉じたときにそのメモリはすべて解放される。設定画面を閉じても、常駐しているプロセスは終了しない。

「一般」の「Volm を再起動」と「Volm を終了」は、名前付きのイベント (`Local\VolmQuit`) で常駐プロセスに終了を頼む。再起動では、そのあとに新しい常駐プロセスを起動する。MyGo の多重起動の防止は、前のプロセスが終わるまで新しいプロセスを待たせるので、2 つが同時に常駐することはない。「終了」は設定画面も閉じる。

「Windows 起動時に起動」の初期値はオンである。インストーラーが Run に登録するほか、インストーラーを使わずに置いた Volm も、設定ファイルがない最初の起動で登録する。`go run` などの開発中のビルドは、一時フォルダーの実行ファイルが登録されてしまうので登録しない。

### 2.10 アイコンとロゴ

アイコンとロゴは `tools/genicons` が Go のコードで描いて書き出す。画像の元ファイルは持たず、図形の一覧 (`tools/genicons/art.go`) から SVG と PNG の両方を作るので、2 つの見た目は一致する。絵を変えるときはこのコードを直して実行し直す。

アイコンは、正面から見た音量のつまみである。Volm はホイールでこのつまみを回すアプリだ、という意味を持たせている。

- 48 × 48 のグリッドに、すべての要素を同じ中心から離して置き、要素どうしを重ねない
- 下が 90° 開いた 270° の目盛りの弧。塗った長さが音量を表す
- 弧の内側に白いつまみ。指針は塗りの終わりを指す
- 弧の開いた下の部分に、小さなスピーカー。このつまみが音のためのものだと示す
- 線は端を丸め、色は単色にする。タイルは藍色 (`#3F3CBB`)、塗りは琥珀色 (`#FFB21E`)、つまみとスピーカーは白

トレイアイコンは、4 つの段階すべてが同じ規則に従う。弧の塗りが 0、1/3、2/3、全部になり、指針がその端を指す。ミュートと 0% はタイルを灰色 (`#6B7280`) にし、スピーカーに × を付ける。タイルに色があるので、ライトとダークのどちらのタスクバーでも見える。

ロゴは、アイコンの右に「Volm」の文字を並べたものである。文字はアイコンと同じく、太さのそろった端の丸い線で描く。文字は白で、アイコンのタイルと同じ藍色で縁取りするので、明るい背景でも暗い背景でも 1 種類のロゴで読める。「o」はアイコンの目盛りと同じく下が開いた琥珀色の弧で、真ん中につまみを表す藍色の丸を置く。「o」の上端はほかの小文字の高さに、開いた部分の端はほかの文字の下端にそろえる。文字のあいだの空きは、斜めの線の「V」も含めて、x ハイトの中ほどの高さで測ってそろえる。

| 出力 | 用途 |
|---|---|
| `assets/icon.svg`、`assets/icon.png` (1024px) | アプリのアイコン。`mygo build` が PNG を実行ファイルのアイコンにする |
| `assets/volm.ico` (16〜256px) | インストーラーのアイコン |
| `assets/logo.svg` | README などのロゴ |
| `internal/tray/icons/*.png` (32px) | トレイアイコン |
| `internal/settings/appicon.png`、`logo.png` | 設定画面のヘッダーと「情報」ページ |

### 2.11 アップデート

設定画面の「更新を確認」と、起動時の自動確認 (初期値はオン、24 時間に 1 回まで) で、新しいバージョンを確認する。

1. GitHub Releases API (`GET /repos/otnc/Volm/releases/latest`) で最新のリリースを取得する。プレリリースを対象にする設定なら `/releases` の先頭を使う
2. タグ (`v1.2.3`) を semver として現在のバージョンと比べる
3. 新しければ、設定画面にバージョンとリリースノートを表示する。自動確認で見つけたときは通知を出す
4. ユーザーが「更新する」を押したら、`Volm-Setup-1.2.3.exe` と `SHA256SUMS` を `%TEMP%` にダウンロードし、SHA-256 を照合する
5. インストーラーを `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART` で起動し、Volm は終了する
6. インストーラーの `[Run]` で新しい Volm を起動する

`SHA256SUMS` は同じリリースに置くので、照合で防げるのはダウンロードの破損だけである。リリース自体の改ざんは防げない。コード署名と更新ファイルの署名 (minisign など) は将来の課題にする。コード署名がない間は、初回のインストールで SmartScreen の警告が出る。

MyGo にも自動更新 (`mygo.Updater`) があるが、NSIS のインストーラーでの導入を前提に、ファイルを直接差し替える方式である。Inno Setup で入れた環境で動くかが文書に書かれておらず、差し替えたあとも Inno のアンインストール情報のバージョンが古いまま残るので、使わない。

## 3. 技術構成

### 3.1 採用する技術

| 用途 | 採用 | 理由 |
|---|---|---|
| 言語 | Go 1.27 | 指定 |
| アプリの枠組み | MyGo (github.com/egoist/mygo、MIT) | トレイ、ウィンドウ、ネイティブ UI、ログイン時起動、多重起動防止をまとめて扱える |
| UI | MyGo のネイティブ UI | WebView2 に依存せず、Go だけで書ける。公式の目安でバイナリ約 7MB、メモリ約 44MB |
| Win32 API | golang.org/x/sys/windows | cgo を使わずに呼べる。MyGo も cgo なしでビルドする |
| COM (Core Audio、WMI、UI Automation) | go-ole、Core Audio は go-wca v0.3.0 | cgo なしで COM を呼べる。go-wca の最終更新は 2023-03 で、足りないインターフェースや誤りのあるメソッドは vtable を自前で呼ぶ |
| ビルド | `mygo build` (`go tool mygo`) | `mygo.json` の名前、バージョン、アイコンを実行ファイルに入れる |
| インストーラー | Inno Setup 6 | 指定 |

go-wca には、次の 2 つの問題があった。実装では該当するメソッドを使わず、vtable を直接呼ぶ。

- `IAudioEndpointVolume.GetMute` と `ISimpleAudioVolume.GetMute` は、Windows が 4 バイトの `BOOL` を書き込む場所に Go の 1 バイトの `bool` を渡す。後ろの 3 バイトが上書きされ、近くの変数の値が壊れる。M1 の実装中に、音量を上げたはずが下がる現象として見つかった
- `IAudioEndpointVolume.RegisterControlChangeNotify` は、コールバックを引数に取らない。`IAudioEndpointVolumeCallback` も定義されていないので、COM オブジェクトを自前で作る

MyGo は 2026-11 時点で v0.10.0 であり、1.0 前なので API が変わりうる。`go.mod` でバージョンを固定し、更新するときは変更点を確認する。

### 3.2 プロセスとスレッド

Volm は常駐プロセスと設定プロセスの 2 つに分かれる。どちらも同じ `volm.exe` で、引数の `--settings` で役割を変える。

常駐プロセスは `RequestSingleInstanceLock` で多重起動を防ぐ。2 つ目を起動したときと、トレイの左クリックや「設定」を選んだときは、設定プロセスを起動する。設定プロセスがすでに開いていれば、新しく起動せずにそのウィンドウを前面に出す。設定プロセスは別の名前で `RequestSingleInstanceLock` を呼び、多重起動を防ぐ。

設定プロセスは `config.json` を書き換えるだけで、常駐プロセスと直接は通信しない。常駐プロセスは `config.json` の変更を監視し、変わったら読み直して反映する。ホットキーの入力欄にフォーカスがある間は、設定プロセスが自分の低レベルキーボードフックでキー入力を受け取る。低レベルフックはあとから登録したものが先に呼ばれるので、常駐プロセスのホットキーより先にキーを受け取れる見込みである (要検証)。

常駐プロセスのスレッド構成は次のとおり。

```
main goroutine (MyGo の main スレッド)
  ├─ トレイ
  └─ RunOnMain で UI を更新

フックスレッド (runtime.LockOSThread で固定)
  ├─ WH_MOUSE_LL / WH_KEYBOARD_LL を登録
  ├─ GetMessage ループ
  └─ コールバックは判定だけ行い、イベントをチャネルに送る

コントローラー goroutine
  ├─ イベントを受けて音量・明るさを変える
  └─ 結果を OSD とトレイに通知

明るさワーカー (モニターごとに 1 つ)
  └─ 最新の目標値を DDC/CI や WMI に書き込む

オーバーレイスレッド (runtime.LockOSThread で固定)
  └─ ソフト減光用の Win32 レイヤードウィンドウとメッセージループ

OSD スレッド (runtime.LockOSThread で固定)
  └─ OSD の Win32 レイヤードウィンドウとメッセージループ
```

低レベルフックのコールバックが時間内 (`LowLevelHooksTimeout`、既定で約 1 秒) に戻らないと、Windows は警告なしにフックを外す。そのため、コールバックではタスクバーの判定と修飾キーの確認 (`GetAsyncKeyState`) だけを行い、COM の呼び出しはコントローラー側で行う。

ソフト減光の覆いは、MyGo のウィンドウではなく Win32 のレイヤードウィンドウ (`WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`) で作る。モニターの数だけ常に表示するウィンドウなので、GPU で描画する MyGo のウィンドウよりメモリを使わない方を選ぶ。

MyGo のアプリは、`OnWindowAllClosed` にリスナーがないと、最後のウィンドウを閉じた時点で終了する。常駐プロセスは空のリスナーを登録しておく。PoC 1 で、ウィンドウを開かずにトレイだけで常駐できることと、ウィンドウを閉じても終了しないことを確かめた。

### 3.4 設定ファイル

`%APPDATA%\Volm\config.json` に保存する。書き込みは一時ファイルに書いてから置き換え、途中で落ちても壊れないようにする。読み込めない場合は、壊れたファイルを `config.json.bak` に退避して初期値で起動し、通知で知らせる。MyGo は Windows の通知をトレイアイコンのバルーンで出すので、応答不可 (集中モード) がオンの間は表示されない。

```json
{
  "version": 1,
  "volume": { "step": 2, "unmuteOnIncrease": true, "middleClickMute": true, "appVolumeWithAlt": true },
  "brightness": {
    "step": 5,
    "softDimMin": 20,
    "monitors": { "MONITOR\\HWP2827\\...": { "method": "auto" } }
  },
  "osd": { "enabled": true, "position": "bottomRight", "durationMs": 1500 },
  "hotkeys": { "volumeUp": ["Win+Up"], "volumeDown": ["Win+Down"], "playPause": ["Ctrl+Shift+Q"], "nextTrack": ["Ctrl+Shift+E"] },
  "update": { "checkOnStartup": true, "prerelease": false, "lastCheckedAt": "2026-11-25T00:00:00Z" }
}
```

`version` は設定の形式のバージョンで、形式を変えたときに移行処理を書くために使う。ログイン時の起動は設定ファイルに持たず、MyGo の `SetOpenAtLogin` / `OpenAtLogin` (HKCU の Run) を正とする。

ログは `%APPDATA%\Volm\volm.log` に書き、1MB を超えたら 1 世代だけ残して切り替える。

## 4. インストーラー

Inno Setup 6 で作る。MyGo の `mygo build -skip-installer` で出力したファイルを Inno Setup でまとめる。

- 管理者権限は求めない (`PrivilegesRequired=lowest`)
- インストール先: `{localappdata}\Programs\Volm`
- `AppId=VolmApp` とする。Inno Setup はこの値でインストール済みのアプリを見分け、アップデートで同じアプリとして上書きする。アンインストール情報のキー名 (`VolmApp_is1`) にもなるので、リリース後は変えない
- `AppPublisher=otoneko.`、`LicenseFile` に GPL-3.0 の全文を指定する
- 言語: `compiler:Languages\Japanese.isl`
- タスク: 「Windows 起動時に起動する」(初期値オン)、「デスクトップにショートカットを作る」(初期値オフ)
- 「Windows 起動時に起動する」は、MyGo の `SetOpenAtLogin` と同じ形で HKCU の Run に登録する。値の名前は `mygo.json` の `identifier` (`io.github.otnc.volm`)、値は `"{app}\Volm.exe" --mygo-opened-at-login` とする。形が違うと、設定画面のスイッチがオフのように見える
- `SetupIconFile` には `assets/volm.ico` を使う
- 実行中の Volm は、インストール前に終了させる (`AppMutex` と `CloseApplications`)
- `[Run]` に Volm を `postinstall nowait` で置き、通常のインストールでは完了画面のチェックで、サイレントインストール (自動更新) では自動で起動する
- アンインストール時: HKCU の Run から Volm を削除する。`%APPDATA%\Volm` を削除するかはダイアログで確認する

出力ファイル名は `Volm-Setup-<version>.exe` とし、`SHA256SUMS` と一緒に GitHub Releases (`otnc/Volm`) に置く。

## 7. 要検証の項目と PoC

実装の前に、次の順で PoC を作って確かめる。

1. MyGo でウィンドウを開かずにトレイだけで常駐できるか。トレイアイコンの差し替え、Explorer 再起動後の復帰、常駐時のメモリ
2. Windows 11 のタスクバーで `WH_MOUSE_LL` によるホイールと中クリックの判定と、イベントを他のアプリに渡さない処理が動くか。管理者権限のウィンドウが前面にあるとき (UIPI) の挙動
3. 内蔵パネルの明るさを WMI で変えられるか。HP 2009 と TOSHIBA LCB2005V は、モニターのメニューで DDC/CI を有効にしたうえで DDC/CI を再確認する
4. ソフト減光の覆いが、全画面の動画やゲーム、HDR を有効にしたモニターで正しく表示されるか
5. タスクバーのボタンから UI Automation でアプリを特定し、音声セッションと対応づけられるか (Windows 10 と 11 の両方)
6. `IPolicyConfig` で既定のデバイスを切り替えられるか
7. Win+↑/↓ を低レベルキーボードフックで処理したとき、Windows のスナップ動作が起きないか

PoC のコードは、結果をこの章にまとめたうえでリポジトリから削除した。コードを見返すときは、最初のコミット `a8288a5` から取り出す。

### PoC 1 の結果 (2026-11-26)

MyGo v0.10.0 で、ウィンドウを開かずにトレイだけで常駐できた。Windows ではトレイアイコンの左クリックで `Tray.OnClick` が呼ばれ、右クリックで `TrayOptions.Menu` のメニューが出る。2.8 の操作はこの仕組みでそのまま作れる。`SetIcon` によるアイコンの差し替えと、2 つ目の起動を `OnSecondInstance` で受け取る処理も動いた。

| 状態 | ワーキングセット | プライベート |
|---|---|---|
| トレイだけ | 20MB | 52MB |
| 設定画面を開いている | 86MB | 118MB |
| 設定画面を閉じたあと | 42〜52MB | 63〜72MB |

設定画面を閉じたあとも、Go のヒープは 1MB 未満だった。増えた分は MyGo の描画まわりのネイティブのメモリで、閉じても戻らない。開閉を 5 回くり返すと、ワーキングセットは 52MB 前後で止まり、ハンドルは 1 回ごとに 2〜6 個増えた。この結果から、設定画面は別のプロセスにした (3.2)。

exe の大きさは、通常のビルドで 16.9MB、`-trimpath -ldflags="-s -w"` を付けると 11.8MB だった。Explorer を再起動したときにトレイアイコンが戻るかは、まだ実機で確かめていない。

### PoC 2 の結果 (2026-11-26)

Windows 11 で `WH_MOUSE_LL` のフックを登録し、ホイールと中クリックを手で操作して確かめた。メインのタスクバー (`Shell_TrayWnd`) とほかのモニターのタスクバー (`Shell_SecondaryTrayWnd`) のどちらでも、ホイールと中クリックを判定できた。コールバックから 1 を返したイベントは、タスクバーに届かなかった。Ctrl、Ctrl+Shift、Alt の状態は `GetAsyncKeyState` で取れた。Chrome のウィンドウの上のホイールはフックが渡し、いつもどおりスクロールした。

フックが受け取る座標は物理ピクセルである。DPI 非対応のプロセスでは、拡大率 125% の画面で `WindowFromPoint` がずれた位置を見てしまい、タスクバーを判定できなかった。常駐プロセスは起動直後に `SetProcessDpiAwarenessContext` で Per-Monitor V2 にする。MyGo がすでに設定している場合は、それを確かめてから二重に呼ばないようにする。

Alt+ホイールのイベントを捨てると、前面のアプリには Alt の押下と解放だけが届き、メニューバーにフォーカスが移る。Alt+ホイールを処理したら、`SendInput` で `VK_NONAME` (0xFC) の押下と解放を送る。メモ帳で試したところ、メニューバーにフォーカスは移らなかった。

コールバックの処理時間は多くが 1ms 未満で、最大 1.56ms だった。6 章の目標 (1ms 以内) を少し超えるので、本番ではルートウィンドウのクラス名を HWND ごとにキャッシュする。管理者権限のウィンドウが前面にあるとき (UIPI) の挙動は、まだ確かめていない。

### PoC 3 の結果 (2026-11-26)

内蔵パネル (SHP158C) の明るさは、go-ole から WMI の `WmiSetBrightness` で変えられた。値は 0〜100 の 101 段階である。1 回の書き込みは、インスタンスを探すクエリを含めて 11〜15ms だった。50 を書いた直後に読み返すと 55 が返った。パネルが明るさを少しずつ変えるためと考えられるので、OSD には読み返した値ではなく、書き込んだ目標値を表示する。

`WmiSetBrightness` の引数は `VT_I4` (Go の `int32`) で渡す。go-ole で `uint8` や `uint32` を渡すと、WMI は「種類が一致しません」というエラーを返した。

外部の 2 台 (HP 2009、TOSHIBA LCB2005V) は、DDC/CI の `GetMonitorBrightness` と VCP 0x10 の読み取りがどちらも「システムに接続されたデバイスが機能していません」で失敗した。失敗が返るまでに 1 回あたり約 250ms かかる。起動時の調査で全モニターを順に調べると 1 秒以上かかるので、調査はコントローラーとは別の goroutine で行い、終わるまでは前回の結果を使う。内蔵パネルは DDC/CI に応答しなかった (I2C の送信エラー) が、WMI が使えるので問題ない。モニターのメニューで DDC/CI を有効にしてからの再確認はまだ行っていない。

### PoC 4 の結果 (2026-11-26)

外部の 2 台に、不透明度 128 の黒いレイヤードウィンドウ (`WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOPMOST | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`) を重ねた。画面の色はタスクバーも含めて約半分の明るさになった (例: `1c1c1c` → `0e0e0e`)。

覆いを重ねた状態でも、`WindowFromPoint` は覆いの下のウィンドウ (`Progman`、`Chrome_WidgetWin_1`、`Shell_SecondaryTrayWnd`) を返した。覆いがある間もタスクバーの判定 (2.1) はそのまま動く。全画面の動画やゲーム、HDR を有効にしたモニターでの表示は、まだ確かめていない。

### PoC 5 の結果 (2026-11-26)

Windows 11 のタスクバーのアプリのボタンは、AutomationId が `Appid: <AUMID>` の形だった (例: `Appid: Brave`、`Appid: Claude_pzs8sxrjxfjjc!Claude`、`Appid: C:\Users\...\Spotify.exe`)。UI Automation の `ElementFromPoint` で AutomationId を取るのに、1 回あたり 2〜5ms かかった。フックのコールバックでは呼ばず、コントローラーで呼ぶ。

明示的な AUMID がない Win32 アプリのボタンは、AUMID が `{6D809377-6AF0-444B-8957-A3773F02200E}\VideoLAN\VLC\vlc.exe` のように、既知フォルダーの GUID と相対パスの形になった。GUID をパスに戻すと、音声セッションのプロセスの実行ファイルと一致した。

VLC (Win32、ほかのモニターのタスクバー) と Brave (音声は子プロセス) で、ボタンから音声セッションを特定し、音量を半分にしてから元に戻せた。パッケージアプリの音声セッションは、確かめる機会がなかった。音声 API は go-wca v0.3.0 (最終更新 2023-03) で足りた。

### PoC 6 の結果 (2026-11-26)

`CPolicyConfigClient` の `IPolicyConfig::SetDefaultEndpoint` (vtable の 13 番目) を eConsole、eMultimedia、eCommunications の順に呼び、既定の再生デバイスをスピーカー (Realtek) から LCB2005V に切り替えてから元に戻せた。3 つの役割の切り替えは合わせて約 100ms だった。この端末で有効な再生デバイスは、スピーカー (Realtek)、LCB2005V、HP 2009 の 3 つである。

### PoC 7 の結果 (2026-11-26)

`WH_KEYBOARD_LL` で、Win が押されている間の ↑/↓ を押下と解放の両方とも捨てた。メモ帳を前面にして `SendInput` で Win+↑ と Win+↓ を送ると、フックがない対照の実行ではメモ帳が最大化された。フックがある実行では、メモ帳の表示状態と位置は変わらなかった。

↑/↓ を捨てると、Windows には Win だけが押されて離されたように見え、スタートメニューが開く。Alt+ホイール (PoC 2) と同じく、処理した時点で `VK_NONAME` の押下と解放を送ると、スタートメニューは開かなかった。ダミーのキーを送らない場合にスタートメニューが開くことは、この PoC では確かめていない。合成した入力で確かめたので、物理キーボードでの確認も実装のときに行う。
